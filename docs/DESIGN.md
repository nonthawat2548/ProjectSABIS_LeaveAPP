# ปรับแต่งหน้าตา Leave

แนวทางของเวอร์ชันนี้รักษาความสดใสของธีมสว่าง และเปลี่ยนชุดสีธีมมืดตามคำขอล่าสุด: ธีมสว่างมีพื้นมิ้นต์ การ์ดขาว และเมนูมิ้นต์อ่อนที่ใช้ตัวอักษรเขียวเข้ม ธีมมืดใช้พื้นเทาชาร์โคล การ์ดเทาที่สว่างขึ้นหนึ่งระดับ ตัวอักษรขาวนวล ปุ่มและลิงก์ฟ้าอ่อน ส่วนเมนูที่เลือกเป็นน้ำเงิน แถบต้อนรับและ Login ไล่สีเทาอมฟ้าในระดับใกล้กัน สีเขียว/พีช/ม่วงยังใช้แยกสถานะและข้อมูลสรุป การ์ดสรุปลดความเด่นของส่วนตกแต่งในธีมมืด ทุกจำนวนบน Dashboard อ่านจากข้อมูลจำลองที่ใช้งานอยู่

## ภาษาและข้อความบนหน้าจอ

หน้า Login ใช้ช่อง “ชื่อผู้ใช้หรืออีเมล” โดยชื่อผู้ใช้ของทั้ง 10 คนเป็นชื่อเฉพาะบุคคล เช่น `pimchanok.w`, `thanawat.k` และ `siriporn.j` ตาม mapping ใน `src/domain/auth.ts` ไม่ใช้ชื่อบทบาทหรือตำแหน่ง รายการแสดงชื่อเต็มกับชื่อผู้ใช้เดียวกับที่ใช้ยืนยันตัวตน เปิดหน้าครั้งแรกหรือเลือก/เปลี่ยนบทบาทให้ช่องข้อมูลและรหัสผ่านว่าง การเลือกบุคคลจากรายการเท่านั้นจึงเติมชื่อผู้ใช้และรหัสทดลอง `1234`; การพิมพ์บัญชีเองไม่เติมรหัสให้ รายการแยกตามบทบาทเดิม และไม่มีการ์ดคำแนะนำรหัสผ่านด้านล่างตามคำขอ 11/10/2569

ตรวจรอบชื่อผู้ใช้เฉพาะบุคคล: `npm test` ผ่าน 174 รายการ, `npm run typecheck`, `npm run build` และ `npm run data:check` ผ่าน ตรวจ Edge headless ทั้ง 10 บัญชี สองธีม และความกว้าง 390/1440px พร้อมพิมพ์ชื่อผู้ใช้เองและลองรหัสเดิม รวม 41 กรณี ไม่พบ page error หรือหน้าล้นแนวนอน ตรวจภาพ Login แล้ว ใช้ฐาน PostgreSQL ทดสอบแยก ไม่เปลี่ยนข้อมูลใช้งานและยังไม่ได้ตรวจบนโทรศัพท์จริง

ข้อความใช้งานใช้ภาษาไทยแบบระบบงานทั่วไป บอกให้ชัดว่าหน้านั้นทำอะไรและผู้ใช้ต้องทำอะไร เช่น “เข้าสู่ระบบ”, “ยื่นคำขอลา”, “สิทธิ์วันลาคงเหลือ” และ “ข้อควรรู้ก่อนยื่นลา” หลีกเลี่ยงสโลแกน คำโฆษณา หรือคำรับรองที่ระบบยืนยันไม่ได้ เช่น “ยื่นลาได้อย่างมั่นใจ” และ “งานที่ดี เริ่มจากการมีเวลาให้ตัวเอง” คงชื่อแบรนด์ภาษาอังกฤษและคำแสดงสถานะตามความหมายเดิม พร้อมระบุบัญชี/ข้อมูลทดลองตามจริง

ใช้ภาษาไทยเป็นภาษาหลักของเมนู ปุ่ม แบบฟอร์ม สถานะงาน ข้อผิดพลาด และคำอธิบายนโยบาย เพื่อให้ผู้ใช้ทำงานได้ด้วยคำศัพท์ชุดเดียวกัน คงชื่อผลิตภัณฑ์ `leave.`/`Leave Management` และ tagline `Space for your balance` เป็นอังกฤษ พร้อม `lang="en"` บนส่วนชื่อแบรนด์ ส่วนหน้าเว็บยังใช้ `lang="th"`

| ส่วนของหน้าจอ | แนวทาง | ตัวอย่าง |
| --- | --- | --- |
| เมนูและข้อมูลสรุป | ภาษาไทย กระชับและตรงกับงาน | พื้นที่ทำงาน, 7 วันข้างหน้า, คำขอรอพิจารณา |
| บทบาทและสถานะงาน | คำไทย พร้อมคำย่อที่มีประโยชน์ | ฝ่ายบุคคล (HR), ทำงานที่สำนักงาน, ทำงานจากบ้าน (WFH), ปฏิบัติงานนอกสถานที่ |
| ชนิดไฟล์และคีย์ลัด | คงชื่อมาตรฐานอังกฤษ | PDF, JPG, PNG, JSON, MB, Ctrl + K (Windows), ⌘ + K (Mac), Esc |
| ข้อผิดพลาดและการเชื่อมต่อ | บอกปัญหาและขั้นตอนถัดไปเป็นไทย | ลองอีกครั้งหรือติดต่อผู้ดูแลระบบ; ไม่แสดงชื่อ environment variable หรือคำสั่งเปิด server ให้ผู้ใช้ทั่วไป |
| ข้อมูลที่คนกรอก | รักษาข้อความต้นฉบับ | ชื่อ ตำแหน่ง เหตุผลการลา ชื่อไฟล์ และความเห็น ไม่แปลหรือแก้ประวัติอัตโนมัติ |

ค่าบทบาท/สถานะ/ช่วงเวลาใน API และฐานข้อมูลยังเป็น enum อังกฤษเดิม ใช้ `src/labels.ts` เป็นค่ากลางเฉพาะการแสดงผล สถานะลาเต็มวันและครึ่งวันต้องใช้คำแปลเดียวกันใน Dashboard, ภาพรวมทีม, ตาราง และรายการมือถือ การเลือกสถานะภาษาไทยยังส่ง `In-office`/`WFH`/`Outside` และวันที่ ISO ค.ศ. ตาม contract เดิม

คำขอ `Pending` ใช้คำว่า “รอพิจารณา” ทั้ง badge ข้อมูลสรุปสิทธิ์ และข้อความตรวจโควตา ส่วนขั้นตอนปรึกษา HR ใช้ “รอความเห็น HR” ให้ตรงกับงานที่กำลังรอ โดยรักษาข้อความในประวัติเดิม

ปุ่มเลือกไฟล์ของเว็บใช้ข้อความไทยและเปิด native file picker เดิม โดยยังปิดใช้งานระหว่างอ่าน/ส่งไฟล์ ภาษาในหน้าต่างเลือกไฟล์ของระบบปฏิบัติการขึ้นกับการตั้งค่าของอุปกรณ์ หัวข้อไทยไม่เพิ่มระยะห่างตัวอักษรแบบหัวข้ออังกฤษ และพื้นที่แสดงสถานะทีมรองรับข้อความไทยที่ยาวขึ้น แนวทางนี้จัดภาษาใน UI ปัจจุบัน ยังไม่มีตัวเลือกสลับทั้งระบบเป็นภาษาอังกฤษ

## แถบด้านบนและท้ายหน้า

ชื่อฝ่ายและตำแหน่งงานของชุดทดลองแสดงภาษาอังกฤษ เช่น IT Department / Software Developer, IT Manager, Systems Analyst, HR Specialist และ Sales Manager ผ่าน labels กลางใน src/labels.ts และ EmployeeLabel; กล่องพื้นที่ทำงานกับข้อมูลบัญชีแสดงตำแหน่งงานจาก Employee.position ส่วน Employee/Manager/HR ยังใช้กำหนดสิทธิ์ ไม่แทนชื่อตำแหน่ง ข้อมูลเดิมและค่าที่ผู้ใช้กำหนดเองไม่ถูกเขียนทับ ชื่อที่ไม่อยู่ในรายการแปลคงตามต้นฉบับ ไม่ต้อง reset ฐานหรือรัน SQL migration

แหล่งอ้างอิงชื่ออาชีพ: [Software Developers](https://www.onetonline.org/link/summary/15-1252.00), [Software Quality Assurance Analysts and Testers](https://www.onetonline.org/link/summary/15-1253.00), [Human Resources Specialists](https://www.onetonline.org/link/summary/13-1071.00) และ [รายชื่ออาชีพ O*NET](https://www.onetonline.org/find/family?f=0) ใช้ชื่อที่เหมาะกับตำแหน่งงานจำลองในโปรเจกต์

แถบด้านบนใช้ข้อความ “ค้นหาเมนูหรือคำขอ” แสดงคีย์ลัดตามอุปกรณ์ (Ctrl + K หรือ ⌘ + K) และซ่อนข้อความ/คีย์ลัดเมื่อพื้นที่ไม่พอ ปุ่มค้นหา ธีม รีเฟรช และแจ้งเตือนมีพื้นที่กด 44px พร้อมคำอธิบายเมื่อชี้เมาส์หรือโฟกัสด้วยคีย์บอร์ด รูปบัญชีใช้ชื่อย่อจากชื่อพนักงานและแสดงชื่อเต็ม ท้ายหน้าคงเพียง “ข้อมูลและนโยบายตัวอย่าง”; คำแนะนำรูปแบบวันที่อยู่กับช่องกรอกวันที่

## กล่องแจ้งเตือน

ปุ่มกระดิ่งด้านบนเปิดกล่องแจ้งเตือนบนหน้าเดิม มีตัวกรองทั้งหมด/ยังไม่ได้อ่าน แบ่งวันนี้และก่อนหน้านี้โดยใช้เขตเวลาไทย รายการเลื่อนภายในกล่องและรองรับจอเล็ก กดรายการเพื่อดูคำขอหรือกดดูการแจ้งเตือนทั้งหมดเพื่อเปิดหน้าเต็ม การเปิดกล่องไม่เปลี่ยนสถานะอ่าน; ปุ่มอ่านทั้งหมดใช้คำสั่งเดิมและรอ snapshot หลังบันทึกสำเร็จ ป้องกันส่งซ้ำและแสดงข้อผิดพลาดในกล่อง ปิดได้ด้วย Escape คลิกนอกกล่อง หรือย้ายโฟกัสออก และปิดเมื่อเปลี่ยนหน้า/เปิด drawer หรือค้นหาด่วน ทุกบทบาทใช้เฉพาะแจ้งเตือนของบัญชีจาก snapshot ตามสิทธิ์

## ค้นหาสถานะเพื่อนร่วมงาน

เมนู “สถานะเพื่อนร่วมงาน” ในพื้นที่ทำงาน (`#/colleagues`) เปิดได้ทุกบทบาท โหลดสถานะพนักงาน active ทุกคนทันทีเมื่อเปิดหน้า รวมเจ้าของบัญชี ค่าเริ่มต้นเป็นวันนี้ ใช้วันที่ วัน/เดือน/ปี พ.ศ. และช่องชื่อ/รหัสเพื่อกรองด้วยชื่อบางส่วน เลขพนักงาน หรือรหัสแสดงผล `EMP-00001` เว้นช่องค้นหาว่างแล้วค้นหา หรือกด “แสดงทุกคน” เพื่อกลับไปดูทั้งหมดในวันที่เลือก

ผลเป็นการ์ดที่แสดงชื่อ รหัส ตำแหน่ง ฝ่าย และสถานะงาน มีข้อความไทยกำกับทุกสถานะ การลาอนุมัติเต็มวันแสดง “ลาเต็มวัน”; ครึ่งวันแยก “ลาครึ่งวันเช้า/บ่าย” คู่กับสถานะเวลาที่เหลือ ไม่มีข้อมูลในวันที่เลือกแสดง “ยังไม่ได้ระบุสถานะ” ไม่สมมติว่าอยู่สำนักงาน ไม่แสดงรายละเอียดคำขอหรือข้อมูลติดต่อส่วนตัว

ช่วงโหลดครั้งแรกและค้นหาปิดช่องกรอก/ปุ่มและแสดงกำลังโหลด มีผลไม่พบและข้อผิดพลาดที่ลองใหม่ได้ การแก้ชื่อหรือวันที่เป็นการเตรียมตัวกรอง โดยรายการเดิมและวันที่ที่ใช้แสดงผลคงอยู่จนกดค้นหา การรีเฟรช snapshot ค้นหาค่าที่ส่งล่าสุดซ้ำ (รวมรายการทั้งหมดเมื่อไม่มีตัวกรอง) และทิ้ง response เก่าที่มาช้า/หลังออกจากหน้า เชื่อม repository ทั้งสองโหมดโดยไม่ขยาย private snapshot ใช้ tokens ธีมเดิมและเรียงช่องกรอก/การ์ดเป็นคอลัมน์เดียวบนโทรศัพท์

## แก้สีและรูปแบบ

เปิด `src/styles.css` ส่วน `:root` คือธีมสว่าง และ `:root[data-theme='dark']` คือธีมมืด เปลี่ยนตัวแปรเหล่านี้เพื่อปรับทุกหน้า:

| ตัวแปร | ใช้กับ |
| --- | --- |
| `--bg`, `--surface`, `--surface-soft` | พื้นหลังและการ์ด |
| `--ink`, `--muted`, `--subtle` | ข้อความหลักและคำอธิบาย |
| `--primary`, `--primary-hover`, `--on-primary` | ปุ่มและลิงก์หลัก |
| `--sidebar`, `--sidebar-muted`, `--sidebar-panel`, `--sidebar-hover` | เมนูด้านข้างและสถานะ hover |
| `--sidebar-active`, `--sidebar-active-ink` | พื้นและตัวอักษรของเมนูที่เลือก |
| `--sidebar-accent`, `--sidebar-accent-ink` | พื้นและตัวอักษรของโลโก้/จำนวนแจ้งเตือน; accent ใช้กับ focus และลิงก์ด้วย |
| `--hero`, `--hero-glow`, `--hero-ink`, `--hero-muted` | ปลายสีไล่ระดับ ตัวอักษรส่วนต้อนรับและหน้า Login |
| `--mint`, `--purple`, `--peach`, `--sky` | กลุ่มสีสถานะและข้อมูลสรุป |
| `--border`, `--control-border`, `--shadow` | ขอบการ์ด ขอบช่องกรอกที่เข้มกว่า และความลึกของการ์ด |
| `--notification`, `--on-notification`, `--scrim` | จำนวนแจ้งเตือนบน header และพื้นหลังทับหน้าของ dialog/drawer |

ตรวจสีข้อความกับสีพื้นหลังเมื่อเปลี่ยนธีม รวมถึงกรณีปุ่ม hover, ช่องกรอก, badge และข้อความรอง อย่าใช้สีเป็นตัวบอกสถานะเพียงอย่างเดียว; คงชื่อสถานะไว้ด้วย

ข้อความรองใช้สีที่อ่านได้ทั้งสองธีม ข้อความขนาดเล็กเดิม 11px ขยับเป็นอย่างน้อย 12px; ชื่อประเภทลา/สถานะ วันที่หลัก ชื่อบทบาท และหัวสถิติใช้ 13px เมนูด้านข้างใช้ 14px น้ำหนัก 500 และไอคอน 20px เส้น 2 ทั้งคอมและโทรศัพท์ หัวแผนกและชื่อบัญชีเพิ่มน้ำหนักเป็น 600 ช่องกรอกและปุ่ม disabled ใช้สีที่อ่านได้โดยไม่ลด opacity ทั้งชิ้น แถบโควตารออนุมัติใช้ลายเฉียงแยกจากส่วนใช้แล้ว ภาพประกอบเฉพาะธีมมืดลดความสว่างและความอิ่มสีผ่าน CSS filter โดยไม่ลด opacity ข้อความหรือเนื้อหาทั้งหน้า การ์ดสถิติใช้ไอคอน 38px บนเดสก์ท็อป; ธีมมืดลดสีขอบบนและวงตกแต่งให้กลืนกับการ์ดมากขึ้น

`tests/theme.test.ts` ตรวจคู่สีจาก CSS ทั้งสองธีม โดยข้อความปกติมี contrast อย่างน้อย 4.5:1 และขอบช่องกรอก/focus อย่างน้อย 3:1 รวมปุ่ม hover, sidebar/แผนก/ไอคอน, badge, avatar, Login, Dashboard, สีตกแต่งสถิติ และปลายทั้งสองของ gradient รวมถึงลำดับความสว่างพื้น/การ์ด/ช่องกรอกธีมมืด การตรวจนี้เป็นการตรวจ palette ไม่ครอบคลุม cascade หรือ layout ทั้งหมด และไม่ใช่การรับรองความสบายตาบนอุปกรณ์จริง จึงต้องตรวจภาพและการใช้งานในเบราว์เซอร์ประกอบ

ขนาดหน้าจอที่มี layout เฉพาะอยู่ใน media queries ท้ายไฟล์ เมื่อกว้างไม่เกิน 760px เมนูเปิดเป็น drawer ทับหน้าเดิม ปิดด้วยปุ่มปิด แตะพื้นหลัง หรือเลือกเมนูได้ ระหว่างเปิดจะล็อกการเลื่อนและการโฟกัสของเนื้อหาด้านหลัง และปิดอัตโนมัติเมื่อเปลี่ยนเป็นหน้าจอกว้าง

คำขอใน Dashboard/ประวัติและสถานะการทำงานมีรายการสำหรับมือถือ แสดงข้อมูลเดียวกับตารางเดสก์ท็อปพร้อมวันที่ พ.ศ. ชื่อพนักงานแสดงตามสิทธิ์เดิม ส่วนตารางสิทธิ์ของ HR และปฏิทินเดือนยังเลื่อนแนวนอนเฉพาะในกรอบได้ หน้า Login บนโทรศัพท์ย่อส่วนภาพประกอบให้เข้าถึงแบบฟอร์มเร็วขึ้น มีตัวเลือกบัญชีครบ 10 คน ช่องกรอกใช้ 16px และปุ่มหลักมีพื้นที่กดอย่างน้อย 44px; ปฏิทินเลือกวันที่เปิดที่ด้านล่างของจอ ขอบหน้าและ drawer เผื่อ safe area ของอุปกรณ์

## จังหวะการเคลื่อนไหวและเข้าสู่ระบบ

หน้า Login เริ่มโดยยังไม่เลือกบทบาทและปิดรายการบัญชีไว้ ผู้ใช้เลือกพนักงาน ผู้จัดการ หรือฝ่ายบุคคลก่อน แล้วรายการจะแสดงเฉพาะบัญชีของหมวดนั้นโดยยังไม่เลือกบุคคล การสลับบทบาทล้างชื่อผู้ใช้และรหัสผ่าน ไม่รวมบัญชีทั้งสามหมวดไว้ใน dropdown เดียว พิมพ์ชื่อผู้ใช้หรืออีเมลเองได้โดยไม่เติมรหัสผ่าน; บัญชีทดลองที่ตรงกันจะปรับหมวดตามบัญชีนั้น ส่วนค่าอื่นคงหมวดที่เลือกไว้ การเลือกหมวดเป็นตัวช่วยกรอกเท่านั้น สิทธิ์จริงมาจากบัญชีที่ repository ยืนยันตัวตน

หลังส่งแบบฟอร์ม Login แสดงหน้าตรวจสอบบัญชี (`checking`) ระหว่างเรียก login แล้วโหลด snapshot ตามสิทธิ์ เมื่อข้อมูลพร้อมแล้วแสดงคำต้อนรับ (`ready`) ก่อนเปิดพื้นที่ทำงานใต้หน้าต้อนรับที่ค่อย ๆ จางออก (`leaving`) ข้อมูลและบัญชีถูกเปิดพร้อมกันเพื่อไม่ให้เห็นหน้าที่โหลดไม่ครบ ใช้เวลาประมาณ 1.2 วินาทีเมื่อข้อมูลพร้อมทันที; การโหลดข้อมูลช้าจะอยู่ในขั้นตรวจสอบต่อโดยไม่รายงานว่าพร้อมก่อนเวลา

ค่าจังหวะอยู่ใน `src/motion.ts`: ตรวจสอบอย่างน้อย 650ms, ต้อนรับ 320ms และออก 240ms ระหว่างขั้นตอนล็อกพื้นหลังด้วย `inert` ป้องกันกดส่งซ้ำ และส่งโฟกัสไปยังเนื้อหาหลักเมื่อเปิดสำเร็จ หากข้อมูลโหลดไม่สำเร็จจะพยายามออกจาก session ที่เพิ่งสร้าง แล้วคืนแบบฟอร์มพร้อมข้อความข้อผิดพลาดและโฟกัสช่องอีเมล Timer ยกเลิกเมื่อ component ถูกถอดออก

ปุ่มตอบสนองต่อการกด การ์ด Dashboard แสดงทีละจังหวะสั้น ๆ และ drawer มือถือเลื่อนเข้า 220ms/ออก 180ms ช่วงปิด drawer จะหยุดรับการกดทันทีและคืนโฟกัส/scroll ให้หน้าเดิม การเปลี่ยนหน้าหลักใช้ opacity เพื่อรักษาตำแหน่งปฏิทินที่ fixed กับ viewport เมื่อเครื่องตั้ง `prefers-reduced-motion: reduce` ปิดการเคลื่อนไหวและข้ามเวลารอเพื่อแสดงผล แต่ยังรอข้อมูลจริงให้พร้อม

## แบบฟอร์มลาคลอด

ส่วนแนบเอกสารร่วมรองรับ PDF/JPG/PNG ไม่เกิน 25 MB ต่อไฟล์ (25 MiB ตามการคำนวณ bytes เดิม) ใช้ค่าจาก `src/domain/attachments.ts` ตรวจชนิดและขนาดก่อนเริ่ม FileReader ปิดปุ่มส่ง/เลือกไฟล์ระหว่างอ่าน และยังเก็บไฟล์ที่เลือกไว้ก่อนหน้าหากอ่านไฟล์ใหม่ไม่สำเร็จ การดาวน์โหลดแปลง base64 ทีละ 64 KiB เป็น TypedArray เพื่อลดการสร้างข้อมูลชั่วคราวขนาดใหญ่ ขนาดเอกสารตั้งแต่ 1 MiB แสดงเป็น MB

เอกสารใหญ่ใน IndexedDB แบ่งเก็บเป็น chunks ภายใน transaction เดียวและอ่านกลับเป็น data URL ตาม interface เดิม ดูรายละเอียดและ compatibility ของข้อมูลเดิมใน `docs/DATABASE.md`

ตัวเลือกลาคลอดยังแสดงเมื่อเพศไม่ผ่านนโยบาย แต่ disabled พร้อมข้อความเฉพาะจาก `maternityGenderIssue()` ซึ่งอ่านข้อมูลเจ้าของคำขอใน snapshot ไม่มีช่องเปลี่ยนเพศในแบบฟอร์ม พนักงานหญิงเลือกกรณีที่ HR เปิดให้เพื่อดู maximumDays, ใช้แล้ว, รออนุมัติ และคงเหลือ หากไม่มีกรณีแสดงข้อความติดต่อ HR พร้อมอีเมล/โทรศัพท์จากข้อมูลเจ้าหน้าที่ที่ใช้งานได้

เมื่อเปลี่ยนประเภทลาล้างค่ากรณีและข้อผิดพลาด เข้าลาคลอดตั้ง Full ตาม quotaScope โดยไม่อ้างอิงเลขประเภทคงที่ ลาคลอดปิด native form validation เพื่อให้กฎ domain ตรวจเพศ/กรณี/ผู้จัดการก่อนข้อผิดพลาดเรื่องวันที่หรือช่องบังคับ หน้าตรวจสอบก่อนส่งแสดงกรณีและสิทธิ์ด้วย การแก้ไขไม่นับ Pending ของคำขอเดิมซ้ำและยังแสดงจำนวนวันของคำขอที่กำลังแก้แยกไว้

HR ใช้เพศของพนักงานที่เลือกเพื่อแสดง/เปิดกรณี ช่องสิทธิ์กรณีใหม่เริ่มจาก defaultQuotaDays ของนโยบาย ส่วนสิทธิ์ที่มีอยู่ใช้ maximumDays ของแต่ละกรณี ทุกวันที่บนหน้าจอยังผ่านฟังก์ชันวันที่ พ.ศ. ของโปรเจกต์

## ฟอนต์และภาพประกอบ

ฟอนต์ **IBM Plex Sans Thai** จากแพ็กเกจ `@ibm/plex-sans-thai@1.1.0` อยู่ใน `public/fonts/` เป็น WOFF2 น้ำหนัก 400/500/600/700 พร้อมไฟล์ใบอนุญาต `OFL.txt` เก็บใบอนุญาตนี้ไว้เมื่อแจกจ่ายโปรเจกต์ ถ้าจะเปลี่ยนฟอนต์ให้แก้ `@font-face` และ `font-family` ใน CSS รวมถึง preload ใน `index.html`

ภาพปฏิทินและต้นไม้ `public/art/leave-garden.svg` และโลโก้ใน `src/ui.tsx` เป็น vector ที่สร้างสำหรับแอปนี้ แก้สีหรือรูปทรงใน VS Code ได้โดยตรง ไม่มีภาพบุคคลหรือภาพจากเว็บอื่นในแอป

## แก้หน้าจอ

- `src/App.tsx`: หน้า Login, แถบเมนู, header, การสลับธีม และปุ่มค้นหา

- `src/Dashboard.tsx`: การ์ดสรุปและ layout หน้าหลัก
- `src/ui.tsx`: hero, โควตา, ทีม, สัปดาห์ถัดไป, คำขอถัดไป และ dialog ค้นหา

- `src/components.tsx`: ตาราง สถานะ ปฏิทินเลือกวันที่ และ dialog ร่วม

ระบบจำธีมด้วยคีย์ `leave-ui-theme` ใน localStorage แต่ยังใช้งานการสลับธีมได้เมื่อเบราว์เซอร์ไม่อนุญาตให้เก็บค่านี้ การค้นหาใช้ snapshot ที่ repository กรองสิทธิ์ตามบัญชีแล้ว และลิงก์ไปยังหน้าจอที่ตรวจสิทธิ์ซ้ำ

วันที่แสดงผลยังต้องผ่าน `src/domain/date.ts`: **วัน/เดือน/ปี พ.ศ.** เช่น `5/12/2569` ส่วน API/ฐานข้อมูลเก็บ ISO ค.ศ. `2026-12-05` ห้ามบวก 543 กับวันที่ที่เก็บในฐานข้อมูล

## ขอบเขตการตรวจสอบ

รอบเปลี่ยนโหมดมืดเป็นเทา–ฟ้าล่าสุด: `npm test` ผ่าน 98 รายการ รวมการตรวจ palette 13 รายการ, `npm run typecheck` และ `npm run build` ผ่าน ตรวจ Edge headless 154 ผ่าน Playwright บน context ทดสอบใหม่แยกจากข้อมูลใช้งาน ครอบคลุม Employee/Manager/HR ทั้งสองธีม 56 สถานะที่ขนาด 1440×1000 และมือถือจำลอง 390×844 รวม Login, Dashboard, คำขอ, แบบฟอร์ม, โควตา, สถานะทำงาน, HR, ปฏิทิน, drawer, ค้นหาด่วน, hover และ date picker คู่ข้อความที่วัด computed style 1,740 ตัวอย่างมี contrast ต่ำสุด 5.00:1 ทั้งสองธีม และ 5.72:1 เฉพาะธีมมืด ไม่พบ page error หรือหน้า overflow แนวนอน พร้อมตรวจภาพ screenshot ประกอบ การวัด computed style ไม่ครอบคลุมพิกเซลของภาพหรือ gradient; tests palette ตรวจปลาย gradient แยกไว้ ยังไม่ได้ลองบนโทรศัพท์จริงหรือประเมินความสบายตาบนจอของผู้ใช้

รอบปรับโทรศัพท์ตรวจปัญหาจากคลิปที่ผู้ใช้ส่ง และเพิ่ม `tests/mobile.test.ts` ตรวจข้อมูลรายการเทียบกับตารางสำหรับ Employee/Manager/HR รวมถึงการเปิด–ปิดเมนู การล็อก scroll/focus และการเปลี่ยนกลับไปจอกว้างผ่าน jsdom การทดสอบนี้ไม่ยืนยันขนาดจริงหรือ layout ในเบราว์เซอร์; เซสชันนี้ไม่มี browser ให้ควบคุม จึงยังต้องตรวจบนโทรศัพท์จริงทั้งแนวตั้ง/แนวนอนและธีมสว่าง/มืด
