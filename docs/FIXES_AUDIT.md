# การแก้ตาม codex_leave_app_fixes (2).md

เอกสารนี้บอกสิ่งที่แก้ในโค้ดและข้อมูลทดลอง พร้อมขั้นตอนนำไปใช้กับฐานเดิม โดยรักษา React + JavaScript, Go + Gin, schema และตารางหลักเดิม ไม่เพิ่มระบบยืนยันตัวตนหรือรีเซ็ตฐานกลาง

## 1. บทบาทและผู้พิจารณา

- Employee ใช้เมนูยื่นลา ประวัติคำขอและสิทธิ์เดิม
- Manager มีเมนูยื่นลา ประวัติคำขอของฉัน (`#/my-requests`) และสิทธิ์ของตน แยกจากงานพิจารณา
- Employee ส่งให้ผู้จัดการที่กำหนด; Manager ส่ง HR ที่ active แบบ Decision โดยไม่มีการอนุมัติตนเอง
- ฉบับ `(1)` เปลี่ยนข้อกำหนดเดิม: **ห้ามส่งคำขอ HR ลงผู้จัดการแผนก** จึงปิดเมนู/URL/API ยื่นและแก้ไขคำขอ HR รวมการเริ่มอัปโหลดสำหรับคำขอตนเอง จนกว่าจะกำหนดผู้อนุมัติระดับสูงกว่าที่ระบบมีอยู่จริง ไม่สร้างบทบาทหรือบัญชีสมมติ
- HR ยังดูประวัติ/สิทธิ์ของตน และถอนคำขอ Pending เดิมได้ ไม่ลบประวัติ HR ที่มีอยู่ มี `#/approvals` สำหรับคำขอผู้จัดการที่ได้รับมอบหมาย
- ตรวจผู้กระทำจาก session/บัญชีล่าสุดทั้ง JavaScript และ Go ห้ามอนุมัติหรือให้ความเห็นคำขอตนเอง แม้เปิด URL/API ตรง
- ผู้จัดการไม่อ่านหรือตัดสินคำขอ HR แม้ managerId/Decision เก่าชี้มาที่ตน ไม่รวม HR ในสรุป/รายงาน/ปฏิทินทีม และไม่เปิดโควตาหรือเอกสารของ HR

จุดหลัก: `src/domain/approvalRouting.js`, `src/domain/service.js`, `internal/service/approval_routing.go`, `internal/service/commands.go`, `src/App.jsx`, `src/routes.jsx`

### ข้อมูล Go/Node ในเครื่อง

`scripts/repair-demo-data.mjs` ดูเฉพาะไฟล์ runtime ที่กำหนด ไม่แก้ JSON ต้นทาง แสดงรายการก่อนแก้เมื่อไม่ใส่ `--apply` และสร้าง `.before-spec-<เวลา>.bak` ก่อนบันทึกเมื่อใส่ `--apply` ซ่อม 1001–1003 และลบเฉพาะคำขอที่มีข้อความทดสอบตามไฟล์กำหนดในเหตุผล/บันทึก/ความเห็น พร้อมข้อมูลลูกของรายการนั้น เก็บบัญชี สิทธิ์ นโยบายและคำขอที่ถูกต้องอื่นไว้ ตรวจตัวตนก่อนแก้และไม่เริ่มไฟล์ runtime ที่ยังไม่มี

```bash
node scripts/repair-demo-data.mjs
node scripts/repair-demo-data.mjs --apply
```

ในการทำงานรอบนี้ซ่อม `server/data/leave-management-go.json` และเก็บสำรองก่อนแก้แล้ว ไฟล์ Node legacy ที่ไม่มีอยู่ถูกข้าม

### Supabase/Vercel ที่ใช้งานอยู่

เครื่องนี้ไม่มีค่าการเชื่อมต่อฐานกลาง จึง **ยังไม่รันการซ่อมกับ Supabase และยังไม่ deploy โค้ดขึ้น Vercel** ขั้นตอนที่ต้องทำต่อกับฐานเดิม:

1. สำรองข้อมูลคำขอและข้อมูลลูกที่กระทบ
2. เปิด Supabase → SQL Editor → New query แล้วคัดลอกทั้งไฟล์ [repair-demo-records.sql](../database/supabase/repair-demo-records.sql) ไป Run
3. ตรวจผลท้ายรายการเป็นคำขอ 1001–1003 ตามตารางข้างบน แล้ว deploy โค้ดนี้ผ่านขั้นตอน Vercel ของโปรเจกต์

**ไม่รัน `setup-10-people.sql` ซ้ำกับฐานที่ใช้งาน และไม่ใช้ปุ่มคืนค่าทั้งฐานแทนการซ่อมนี้** SQL ใช้ transaction/advisory lock เดิม ตรวจตัวตนชุดทดลอง/ประเภทลา/สิทธิ์รายปีก่อนแก้ สร้างเลขข้อมูลลูกต่อจากฐานเดิม และผูกสิทธิ์ตาม employee/type/year จริง ไม่สมมติเลข entitlement จากไฟล์ตัวอย่าง

ตัวสร้าง SQL คือ `scripts/generate-demo-repair.mjs` ไม่เชื่อมฐานใด ใช้ PGlite ทดสอบ SQL กับฐานแยก รวมการเก็บคำขออื่นไว้

## 3. เมนูและการแก้ไข/ถอนคำขอ

คืนเมนูการแจ้งเตือนใน sidebar/mobile drawer ทุกบทบาทตามไฟล์กำหนดล่าสุด กระดิ่ง กล่องแจ้งเตือน ป๊อปอัปและหน้าเต็มยังอยู่ เจ้าของคำขอ Pending ที่ยังเปิดยื่นลาได้แก้ไขหรือถอนผ่านกล่องยืนยันได้ ส่วน HR ถอน Pending เดิมได้แต่ไม่เปิดแก้ไขเพื่อส่งลงผู้จัดการ การถอนคืนยอดรอพิจารณาทันทีจากสถานะคำขอ เมื่ออนุมัติ/ไม่อนุมัติแล้วไม่มีสองปุ่มนี้ และ backend ตรวจเจ้าของ/สถานะ/version ซ้ำ

## 4. การปรึกษาและการตัดสิน

ผู้จัดการต้องใส่บันทึกก่อนส่งปรึกษา HR แสดง “อยู่ระหว่างปรึกษา HR” และแจ้งผู้รับ HR ให้ความเห็นผ่าน Consultation พร้อมบันทึกเวลาและแจ้งผู้จัดการ การให้ความเห็นคำขอ Employee ไม่ใช่การอนุมัติ ผู้จัดการที่ได้รับมอบหมายเป็นผู้ตัดสินขั้นสุดท้าย การไม่อนุมัติต้องระบุเหตุผล และทั้งผลอนุมัติ/ไม่อนุมัติแจ้งเจ้าของคำขอ

กรณี HR อนุมัติคำขอ Manager ใช้ Decision แยกจาก Consultation ตามข้อ 1 จึงไม่เปิดให้ HR ตัดสินคำขอ Employee ที่เพียงส่งมาปรึกษา

## 5. สถานะทำงานและความเป็นส่วนตัว

สถานะวันลาที่อนุมัติอ่านจาก `Leave_Request` + `Leave_Day` ที่บันทึกไว้ ไม่คำนวณวันเดิมใหม่หรือเขียนสถานะซ้ำจนขัดกัน เมื่อเลือกวันนั้นหน้า work/colleagues แสดงการลาอัตโนมัติ ล็อกช่องและการบันทึกทั้งเต็มวันและครึ่งวัน; backend ปฏิเสธการเขียนทับด้วยสถานะทำงาน

หน้าเพื่อนร่วมงานคืนเฉพาะชื่อ รหัส ตำแหน่ง ฝ่าย สถานะและช่วงเต็ม/ครึ่งวัน ไม่ส่งประเภทลา เหตุผล ใบรับรองแพทย์หรือกรณีลาคลอด เอกสารแนบตรวจสิทธิ์คำขอทุกครั้ง ไม่ใช้สิทธิ์ดูโปรไฟล์เป็นสิทธิ์อ่านเอกสาร

ยอดใช้แล้ว/รอพิจารณา/คงเหลือคำนวณจากวันลาที่ผูกสิทธิ์และสถานะคำขอ จึงเปลี่ยนทันทีเมื่ออนุมัติ/ปฏิเสธ/ถอน โดยไม่สร้างยอดสะสมซ้ำในตาราง

## 6. ตรวจเงื่อนไขและกรณีขอบ

- วันทำงานไม่นับเสาร์–อาทิตย์และวันหยุด ช่วงที่ไม่มีวันทำงานยื่นไม่ได้
- ลาคลอดตรวจเพศจากบัญชีจริง นับวันปฏิทิน และกรณีต้องไม่เกิน 120 วัน
- ครึ่งวันต้องวันเริ่ม/สิ้นสุดเดียวกัน นับ 0.5 วัน
- พักร้อน/กิจยื่นล่วงหน้าอย่างน้อย 1 วันตามนโยบาย ป่วยย้อนหลังได้ไม่เกิน 30 วันนับจากวันเริ่ม ป่วยตั้งแต่ 3 วันทำงานต้องมีใบรับรองแพทย์
- เอกสารใหม่ PDF/JPG/PNG ไม่เกิน 25 MiB ตรวจขนาด/ชนิด/เนื้อหาเดิม Employee/Manager แนบคำขอของตนได้
- ช่วงวันที่ทับ Pending/Approved ของตนยื่นไม่ได้ แม้เป็นเช้ากับบ่ายของวันเดียวกัน
- ยอดอนุมัติ + รอพิจารณา + คำขอใหม่ต้องไม่เกินสิทธิ์รายปี/รายกรณี ใช้ปีของวันลา ข้ามปีแยกคำนวณตามเดิม

## 7. BIS Analytics ใน Dashboard
