# Leave · ระบบจัดการการลา

แอปภาษาไทยสำหรับ **พนักงาน / ผู้จัดการ / HR** ต่อยอดจาก Screen Design และ Navigation Flow ในงานนี้ พร้อมข้อมูลจำลองที่บันทึกได้ และ REST adapter สำหรับเปลี่ยนเป็นหลังบ้านของคุณภายหลัง

**วันที่บนหน้าจอและช่องกรอกใช้ วัน/เดือน/ปี พ.ศ. เช่น `5/12/2569`** ไม่ใช่เดือน/วัน/ปี ส่วน API และฐานข้อมูลใช้ `2026-12-05` (ค.ศ.)

## หน้าตาเวอร์ชันใหม่

- โทนเขียวเข้มและมิ้นต์ พร้อมภาพประกอบปฏิทิน/ต้นไม้ที่แก้ไขไฟล์ SVG ได้
- ฟอนต์ IBM Plex Sans Thai เก็บในโปรเจกต์ เปิดได้โดยไม่ต้องเรียกบริการฟอนต์ภายนอก
- ธีมสว่าง/มืด จำค่าที่เลือก และใช้ค่าธีมของเครื่องเมื่อเปิดครั้งแรก
- Dashboard แยกตามบทบาท แสดงโควตา สถานะทีม คำขอล่าสุด และวันลาที่กำลังจะมาถึงจากข้อมูลจริงในชุดจำลอง
- ค้นหาเมนูหรือคำขอด้วยปุ่มค้นหา หรือ `Ctrl+K` / `⌘+K` แล้วปิดด้วย `Esc`
- แบบฟอร์มแสดง 3 ขั้นตอน ช่วยบอกว่ากำลังกรอก ตรวจสอบ หรือส่งคำขอแล้ว
- จัดวางใหม่ตามขนาดหน้าจอ และลด animation เมื่อเครื่องตั้งค่า Reduce Motion

ดูวิธีแก้สี ฟอนต์ ภาพประกอบ และแหล่งอ้างอิงใน [docs/DESIGN.md](docs/DESIGN.md)

1. แตก ZIP แล้วเปิดโฟลเดอร์ `leave-management` ด้วย **File → Open Folder** ใน VS Code
2. ติดตั้ง Node.js **22.12 ขึ้นไป** (ใช้ Node.js 24 ได้)
3. เปิด Terminal ใน VS Code แล้วรัน:

```bash
npm install
npm run dev
```

## ทดลองเชื่อมหลังบ้านจำลอง

หยุดคำสั่งเดิมด้วย `Ctrl+C` แล้วรัน:

```bash
npm run dev:api
```

คำสั่งนี้เปิดทั้งหน้าเว็บและ **Node.js mock REST server** ให้เอง หน้าเว็บเชื่อม `/api` ผ่าน Vite proxy ไปที่ `127.0.0.1:3001`

- ข้อมูลหลังบ้านบันทึกใน `server/data/leave-management-10-people.json` และยังอยู่หลังรีสตาร์ต server; ตั้ง `MOCK_DATA_FILE` เพื่อใช้ไฟล์อื่นได้
- เมื่อยังไม่มีไฟล์ข้อมูล จะเริ่มต้นจาก `src/data/leave-management-10-people.json` และบันทึกเป็นไฟล์ runtime เมื่อทำรายการที่เขียนข้อมูล
- เก็บ `server/data/db.json` เดิมไว้ ไม่มีการย้ายหรือเขียนทับอัตโนมัติ
- บัญชีตัวอย่างเหมือนโหมดเบราว์เซอร์
- ใช้ cookie session ฝั่ง server; การอนุมัติและตรวจสิทธิ์ทำที่ server
- โหมด API และโหมดเบราว์เซอร์เริ่มต้นด้วยชุด 10 คนเดียวกัน แต่บันทึกการเปลี่ยนแปลงแยกกัน **ไม่มีการย้ายหรือซิงก์ข้อมูลอัตโนมัติ**
- server จำลองทำงานที่ localhost เพื่อพัฒนา คุณเปลี่ยนการเก็บ JSON เป็น SQL database ได้ภายหลัง
- รีเซ็ตเป็นชุด 10 คนผ่านบัญชี HR → การตั้งค่า → คืนค่าข้อมูลจำลอง หรือ `npm run seed -- --confirm` สำหรับโหมด API; การคืนค่าจะล้างการแก้ไขในฐาน runtime ที่เลือกใช้อยู่

หากต้องการเปิดสอง Terminal แยกกัน:

1. คัดลอก `.env.example` เป็น `.env` แล้วตั้ง `VITE_DATA_MODE=api`
2. Terminal แรก: `npm run mock:server`
3. Terminal ที่สอง: `npm run dev`

ค่า `MOCK_PORT` ใน `.env` เปลี่ยน port ของ server และ Vite proxy ได้

## เปลี่ยนเป็นหลังบ้านของคุณ

ดูรายละเอียดใน [docs/API.md](docs/API.md) และ [docs/DATABASE.md](docs/DATABASE.md)

1. สร้าง API ตาม contract ที่เตรียมไว้ หรือปรับ `src/data/apiRepository.ts` ให้ตรงกับ API ของคุณ
2. ตั้งค่าใน `.env`:

```dotenv
VITE_DATA_MODE=api
VITE_API_BASE_URL=/api
```

3. ถ้าใช้ server อื่น ให้แก้ proxy ใน `vite.config.ts` หรือใส่ URL API ของคุณใน `VITE_API_BASE_URL` และตั้งค่า CORS/cookie ให้รองรับ
4. ข้อมูลตารางหลักใน `database/schema.sql` ยึด 9 ตารางเดิม พร้อมระบุส่วนเพิ่มที่แอปใช้ไว้ในคู่มือ
5. ชุด 10 คนที่แอปใช้อ่านเริ่มต้นอยู่ใน `src/data/leave-management-10-people.json` พร้อมไฟล์ SQL/SQLite ในโฟลเดอร์เดียวกัน ส่วน `database/mock-db.json` และ `database/mock.sqlite` เป็นตัวอย่างเดิมสำหรับอ้างอิง Mock REST server ใช้ JSON และยังไม่ได้เชื่อม SQLite โดยอัตโนมัติ

**ไม่มีรหัสฐานข้อมูลหรือ secret ใน frontend** ค่า `VITE_*` จะอยู่ในไฟล์เว็บ จึงใช้เฉพาะ URL/โหมดเท่านั้น ระบบยืนยันตัวตนในชุดนี้เป็นบัญชี demo; ก่อนใช้ข้อมูลพนักงานจริงให้เปลี่ยน login/session และจัดการสิทธิ์ที่หลังบ้านของคุณ

## การทำงานที่มีให้

### พนักงาน

- Dashboard, สิทธิ์รวม/ใช้แล้ว/คงเหลือ/รออนุมัติ
- ยื่นลาพักร้อน ลาป่วย ลากิจ และลาคลอดตามสิทธิ์
- เลือกวันที่จากปฏิทิน พ.ศ. หรือพิมพ์ `5/12/2569`
- ลาเต็มวัน / ครึ่งวันเช้า / ครึ่งวันบ่าย (ครึ่งวันต้องวันเดียวกัน)
- ตรวจวันลาซ้อน เงื่อนไขล่วงหน้า โควตา และใบรับรองแพทย์
- แนบ PDF/JPG/PNG จริง ขนาดไม่เกิน 2 MB และดาวน์โหลดกลับได้
- ตรวจสอบก่อนส่ง ดูประวัติ ค้นหา กรอง และติดตาม timeline
- แก้ไขหรือยกเลิกเฉพาะคำขอที่ยังรอพิจารณา
- สถานะการทำงานและการแจ้งเตือน

### ผู้จัดการ

- ดูคำขอของทีม ดูเอกสาร และตรวจสิทธิ์ของผู้ยื่น
- อนุมัติ / ไม่อนุมัติพร้อมเหตุผล / ส่งปรึกษา HR
- ระหว่างรอความเห็น HR จะยังไม่ให้ตัดสินผลคำขอ
- ตรวจโควตาล่าสุดก่อนอนุมัติ ป้องกันอนุมัติซ้ำและข้อมูลเก่า
- ปฏิทินการลา สถานะการทำงานของทีม และการแจ้งเตือน

### HR

- ดูคำขอที่ได้รับมอบหมายและส่งความเห็นกลับผู้จัดการ
- ความเห็น HR ไม่เปลี่ยนสถานะเป็นอนุมัติ และไม่หักโควตา
- ดูข้อมูลพนักงาน จัดสรรสิทธิ์รายปี และเปิดกรณีลาคลอด
- ตั้งค่าล่วงหน้า เกณฑ์เอกสาร โควตาตั้งต้น และวันหยุด
- ปฏิทิน/สถานะการทำงาน ส่งออก snapshot JSON และคืนค่าข้อมูลจำลอง

## กฎที่ใช้ในข้อมูลตัวอย่าง

- พักร้อน 10 วัน / ลาป่วย 30 วัน / ลากิจ 6 วัน ต่อปี; ลาคลอด 120 วันต่อกรณี **เป็นค่าจากตัวอย่างและ Data Dictionary ไม่ใช่การรับรองนโยบายหรือข้อกฎหมาย**
- พักร้อน/ลากิจ/ลาคลอดยื่นล่วงหน้าอย่างน้อย 1 วัน; ลาป่วยย้อนหลังไม่เกิน 30 วันใน demo
- ลาป่วยตั้งแต่ 3 วันต้องมีเอกสาร
- ประเภทวันทำงานไม่นับเสาร์–อาทิตย์ และวันหยุดที่ HR เพิ่มเอง **ไม่มีปฏิทินวันหยุดราชการอัตโนมัติ**
- ลาคลอดนับวันตามปฏิทินและใช้โควตาต่อกรณี
- โควตาคงเหลือหักเฉพาะรายการที่อนุมัติ แต่ตรวจวันที่รออนุมัติด้วยเพื่อกันยื่นเกินสิทธิ์
- คำขอข้ามปีแบ่งสิทธิ์ตามปีของแต่ละวัน
- แก้ไขคำขอแล้วความเห็นเดิมจะถูกยกเลิกและเริ่มพิจารณาใหม่
- เปลี่ยนวันหยุดไม่มีผลย้อนหลังต่อจำนวนวันของคำขอเดิม จนกว่าจะมีการแก้ไขคำขอ
- `Leave` ในสถานะทำงานมาจากคำขอที่อนุมัติ ไม่สามารถเลือกให้ตัดโควตาเองได้

ข้อมูลต้นทาง 10 คนถูก clone ผ่าน `createDemoDatabase()` สำหรับเริ่มต้นและคืนค่าข้อมูล การแก้ source JSON ไม่เขียนทับข้อมูลที่ใช้อยู่เอง หากแก้ตัวสร้างข้อมูล ให้สร้าง JSON ใหม่ตาม [src/data/README.md](src/data/README.md) แล้วใช้การคืนค่าของ HR เมื่อต้องการนำชุดใหม่เข้าสู่ฐาน runtime

ชุดฐานข้อมูลจำลอง **10 บัญชี** ใน [src/data/README.md](src/data/README.md) เชื่อมเป็นข้อมูลเริ่มต้นของแอปทั้งสองโหมดแล้ว ไฟล์ SQLite/SQL เป็นสำเนาส่งออกสำหรับตรวจดูหรือนำไปใช้ต่อ และมี Data Dictionary สำหรับอ้างอิง การทำรายการในแอปไม่ซิงก์กลับไปยังไฟล์ต้นทางหรือไฟล์ส่งออกเหล่านี้

ผล build อยู่ใน `dist/` ใช้เป็น static web app ได้ ตัวเว็บที่เผยแพร่ให้ทดลองใช้โหมด IndexedDB; mock Node server อยู่ในไฟล์โปรเจกต์สำหรับรันบนเครื่องของคุณ **ไม่ได้รันอยู่ในเว็บทดลองออนไลน์**

## ผลตรวจสอบเวอร์ชันนี้

ทดสอบวันที่ พ.ศ./ปีอธิกสุรทิน/เวลาไทย, เงื่อนไขลา, โควตาและการอนุมัติซ้ำ, HR consultation, สิทธิ์ตามบทบาท, ครึ่งวัน, ข้ามปี, ลาคลอด, วันหยุด, การค้นหาจากข้อมูลที่บทบาทมีสิทธิ์เห็น, การนับพนักงานลาโดยไม่ซ้ำคน, การ render ทุกหน้าจอ และ mock HTTP API รวมทั้งการเขียนข้อมูลลงไฟล์

ตรวจ TypeScript และ production build แล้ว การตรวจด้วยเบราว์เซอร์จริงในรอบนี้ยังไม่ได้ทำเนื่องจากเครื่องมือ preview สำหรับโปรเจกต์ไม่พร้อม

## สิ่งที่เพิ่มจาก Data Dictionary เพื่อให้หน้าจอทำงานครบ

`Withdrawn`, ครึ่งวัน/จำนวนวันแบบ 0.5, request version, timeline, cancellation ของการพิจารณาเดิม, สถานะ consultation `Completed`, ข้อมูลฝ่าย/active, การแจ้งเตือน และวันหยุด ดู mapping ใน `docs/DATABASE.md`

ข้อมูลพนักงานและเอกสารใน seed เป็นข้อมูลสมมติทั้งหมด สามารถแก้ ปรับ หรือต่อยอดโค้ดในโปรเจกต์นี้ได้
